# 车载速度记录 · 采样接入与分段线性压缩工具

纯前端单页工具（无构建、无依赖）：导入带时间戳的速度点，按**速度误差**与**里程误差**双预算做分段线性压缩，生成可下载、可独立解码核对的 JSON 文件，并对照原始曲线查看误差落点。

直接用浏览器打开 `index.html` 即可（`file://` 可用，无需服务器）。

## 功能对照

| 需求 | 实现 |
|---|---|
| 网页导入带时间戳的速度点 | 第 1 区：粘贴 / 上传 CSV，表头 `time,speed,unit,flag`（或无表头前两列）；时间支持相对秒、epoch 秒/毫秒、ISO 字符串 |
| 采样间隔不固定 | 算法只依赖逐点时间戳，示例"短尖峰"即 10s/1s 混合采样 |
| 速度统一换成米每秒 | 行内 `unit` 列或全局默认单位（km/h、m/s、mph），导入即换算 |
| 设置速度/里程误差预算 | 第 2 区，修改即重新压缩核对 |
| 每段用首尾采样点连线 | 压缩器贪心选取**满足两类限制的最远终点**，并**检查全部候选**（可行性不随终点单调，不提前退出） |
| 速度误差逐点不超 | 解码后每个原采样时刻 `|v解码 − v原始| ≤ 速度预算` |
| 里程不失真 | 以原始相邻点梯形积分为基准；每个连续区间内**累计有符号里程偏差**在**每个原采样时刻**的绝对值都 ≤ 里程预算（不是只看末端，正负偏差抵消不算数；累计值跨段结转） |
| 停机标记 / 采样缺口切断 | `flag=stop` 或相邻间隔超过阈值即切断连续区间；两侧不插值、缺口里程不凭空补算 |
| 同刻冲突隔离 | 相同时间戳且速度冲突的记录整组隔离、原值保留（第 3 区），可选定一条并修正数值后重算 |
| 导出文件自描述 | JSON 含 `units`（s / m/s / m）、`params`（两类预算 + 缺口阈值）、分段断点与断开口（gap/stop）信息 |
| 独立解码器 | 校验回路：压缩 → 序列化为文件文本 → 解码器**只读文本** → 与原始输入逐点核对；第 5 区可上传已下载文件独立复核 |
| 展示实际结果 | 统计卡片展示实际文件字节数、保留断点数、实测最大误差与预算利用率；图表是核对结果的可视化，不替代文件校验 |
| 定位最接近上限的一段 | 按预算利用率（速度/里程取大）找出最接近上限的分段，图表高亮 + 表格定位 |
| 边界验证数据 | 内置示例：匀速、短尖峰、长缺口+停机、累计偏差先增后减（末端偏差≈0、中点最大）、同刻冲突 |

## 文件格式（veh-speed-plc v1）

```json
{
  "format": "veh-speed-plc",
  "version": 1,
  "units": { "time": "s", "speed": "m/s", "distance": "m" },
  "params": { "speedEps": 0.5, "distEps": 20, "gapThreshold": 60 },
  "generatedAt": "2026-11-22T…",
  "runs": [
    { "breakBefore": null, "points": [[0, 13.89], [600, 13.89]] },
    { "breakBefore": { "reason": "gap", "gapSeconds": 660 }, "points": [] },
    { "breakBefore": { "reason": "stop", "at": 1210, "gapSeconds": 20 }, "points": [] }
  ]
}
```

- `runs[].points`：分段线性断点 `[秒, 米每秒]`，段内线性插值，区间之间不插值。
- `breakBefore`：该区间相对上一区间的断开口（`gap` 超阈值缺口 / `stop` 停机标记）。
- 解码器只依赖本文件；核对时以原始输入的每个采样时刻为检查点。

## 算法要点（core.js）

- **切分**：排序去重（同刻同值去重、同刻异值隔离）→ 按停机标记与超阈值缺口切成连续区间。
- **压缩**：每区间内贪心。起点 `i` 固定时逐一检查候选终点 `j`（全部检查，因为换终点即换弦，可行性不单调），取最远可行者；段 `i→j` 可行当且仅当：
  1. 段内每个原采样时刻，弦值与原始速度之差 ≤ `speedEps`；
  2. 设 `C` 为之前各段结转的累计里程偏差，段内每个原采样时刻 `|C + D_m| ≤ distEps`（`D_m` 为段内弦积分与原始梯形积分之差）。
- 相邻两点段恒可行（弦过两端点、区间梯形一致），故贪心必然终止。
- **核对**：逐采样点重算上述两类误差，并给出每分段预算利用率；全程只读导出文件文本。

## 测试

```bash
node test/run-tests.js    # 核心算法：72 项断言（含全部边界用例），零依赖
node test/smoke-ui.js     # 页面冒烟：27 项（需 jsdom；未安装自动跳过）
```

关键边界用例：

- 匀速 61 点 → 2 断点、零误差；
- `v=[0,10,12,21]`：`j=2` 超速度预算、`j=3` 反而可行 → 证明候选终点必须全检查；
- `v=[10,12,10,8,10]`：整段末端里程偏差为 0、中点达 2m → 证明逐时刻检查不可省；且 `j=3` 失败、`j=4` 可行 → 里程约束同样非单调；
- `v=[10,9.6,10,20,19.6,20,20]`：首段结转 +0.4m，后续段局部偏差各自不超限但结转后超限 → 证明累计值跨段结转；
- 缺口 180s / 停机标记切断区间，缺口内解码返回 `null`，里程只覆盖连续区间；
- 篡改下载文件中的断点 → 上传复核如实报"核对未通过"。

## 说明与限制

- 压缩为精确贪心（对每个起点检查全部候选），单区间复杂度约 O(n²)~O(n³)；万级采样点的单区间在浏览器中可用，更大的数据建议先按行程切分。
- 时间解析：绝对值 ≥1e11 视为 epoch 毫秒，≥1e8 视为 epoch 秒，其余视为相对秒。
- 缺口阈值设为 0 表示"不按缺口切分"（仅停机标记切断）。
